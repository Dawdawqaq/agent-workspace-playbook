# Agent 工作区协作手册

[English](README.md)

一套以 Git 为基础的轻量流程，供人和编码 Agent 在同一个项目里协作。新会话应能找到正确的仓库、理解任务、完成一次有效验证，并交代本轮留下的资源。

## 快速开始

1. 确定项目工作区。新建单产品项目时，把项目目录作为 Git 根，并在该目录运行 `git init -b main`。已有项目沿用原有仓库布局，在工作区入口指明该进入哪个仓库。
2. 使用[中文模板](templates/zh-CN/)。新项目可直接复制，已有项目按需合并。填写实际范围、Git 根、启动命令与验证命令。
3. 分派时给 Agent **角色、任务链接和基线提交**。会话已在项目工作区时，由入口提供仓库路径即可。
4. 让 Agent 从 `AGENTS.md` 开始，核对工作树，执行第一项相关验证，并按指定提交报告结果。

| 文件 | 维护的事实 |
| --- | --- |
| [AGENTS.md](templates/zh-CN/AGENTS.md) | 入口、项目路径和必要约束 |
| [PROJECT.md](templates/zh-CN/PROJECT.md) | 产品范围与边界 |
| [PLAYBOOK.md](templates/zh-CN/PLAYBOOK.md) | 角色、验证和资源安全 |
| [STATUS.md](templates/zh-CN/STATUS.md) | 当前交接、基线和阻塞 |
| [任务模板](templates/zh-CN/tasks/TEMPLATE.md) | 范围、验收、证据与交接 |

## 按任务选最轻的流程

- **小改动**：一张任务、一位负责人和一项定向检查。项目有约定或变更风险较高时，再做独立验收。
- **长项目**：按可验证的用户结果分批。每次交接留下提交、最后通过的检查、阻塞和下一条可执行动作。
- **并行任务**：共享接口只有一个负责人，必要时隔离源码副本和运行资源。明确谁负责集成、怎样核对合并后的行为。

## 让工作区能安全收尾

每次验证使用独立的、已忽略的运行目录。登记运行 ID、归属、输出路径，以及本轮使用的进程、容器或卷。验证后留下最少的脱敏证据，确认资源已停止，再预览并按编号回收。共享缓存、用户数据和归属不明的文件单独盘点。会话关闭或端口空闲，单凭这些无法确认资源能安全清理。

换环境后，重新核对 Git 根、工具、写入权限和相关运行限制。检查受阻时，记录原因及实际完成的较小验证。测试报告标明精确提交和证据覆盖范围。

## 跑一个最小示例

在仓库根目录运行：

```sh
python3 examples/smoke.py
```

Windows 安装了 Python 启动器时，也可使用 `py -3 examples/smoke.py`。示例只使用合成数据和 Python 标准库，展示一条可以实际运行的验收条件。冷启动交接时，只给新会话入口、[示例任务](examples/CHECK.md)和提交，观察它能否独立找到并执行同一项验证。

本仓库提供模板与示例。各项目按自身情况配置运行验证、权限和清理命令。
